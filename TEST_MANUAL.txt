  "Show me my subscription list"

TEST 4 — Question Recommendations
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

After each chat response, Finley generates 3 follow-up question suggestions
tailored to what was just answered. These appear as clickable chips.

Steps:
  1. Ask any question (data or advice)
  2. Wait for the response to complete
  3. Look below the response for 3 suggested follow-up questions
  4. Click one of them

Pass:
  - 3 follow-up suggestions appear after every response
  - Suggestions are specific to the answer (not generic filler questions)
  - Clicking a suggestion auto-submits it as the next message
  - The follow-up answer is consistent with the previous response

Fail indicators:
  - No suggestions appear after the response
  - Suggestions are generic ("Tell me more", "What else?")
  - Clicking a suggestion does nothing

Tests whether follow-up questions work without repeating context.
Finley keeps the last 8 message pairs in memory during a session.

Steps:
  1. Ask: "How much did I spend on dining last month?"
  2. Wait for the answer
  3. Ask: "How does that compare to the month before?"
  4. Ask: "Which restaurants came up most often?"

Pass:
  - Each follow-up correctly refers to the topic from step 1
  - "that" and "the month before" are interpreted correctly without clarification
  - Figures stay consistent across the conversation

Fail indicators:
  - "I'm not sure what you're referring to"
  - Finley treats each question as a fresh conversation with no memory
  - Contradictory figures across turns

TEST 6 — Cross-Session Semantic Memory (vector search)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Finley remembers advice answers across separate sessions using semantic
vector search. Each advice answer is embedded as a 384-number vector and
stored locally. When a similar question comes in, the closest match is
retrieved and injected into context — even if the wording is different.

Only advice answers are stored (data lookups go stale as transactions change).

Session 1:
  1. Start the app, load data
  2. Ask: "Should I pay off my credit card or start investing?"
  3. Get the full answer
  4. Close the browser and stop the app (Ctrl+C in terminal)

Session 2:
  1. Restart the app (streamlit run app.py), load data again
  2. Ask a similarly-worded but different question:
     "Is it better to clear my debt before putting money into savings?"

Pass:
  - The response in Session 2 aligns with or references the advice from Session 1
  - In the terminal running Finley, you should see:
    "Relevant context from previous conversations:" printed before the API call
  - The answer feels informed by the prior session, not starting from scratch

Fail indicators:
  - Session 2 answer completely ignores the prior advice
  - No terminal output indicating memory retrieval
  - App crashes on startup (check if .finley_memory/ folder exists)

How it works (for reference):
  - Model: all-MiniLM-L6-v2 (sentence-transformers, ~22MB, runs locally)
  - Storage: .finley_memory/conversations.json + embeddings.npy
  - Search: cosine similarity — incoming question converted to 384 numbers,
    compared against all stored question vectors, closest match above 0.55
    similarity is injected into the system prompt
  - No external vector database — runs entirely on disk using numpy

Check the terminal running Finley for routing output.

  "What is my total spending this year?"
    → Should route to Python (instant answer, $0 cost)

  "How much did I spend on coffee?"
    → Should route to Haiku (data lookup, 3–8 seconds)
